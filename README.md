# 网络拓扑 · 接口测试控制台

一个零依赖的前端项目，用图形化界面直接测试后端 REST 接口。所有 `/api/*` 请求经本地 Node 代理转发到 `http://127.0.0.1:8080`，**前后端同源，不需要改后端 CORS 配置，也不需要 npm install**。

> **项目位置**：前端 `E:\code\topology-console`，后端 `E:\code\network-topology`，两者是平级的独立项目。

> **当前后端为 v3**：全系统分成两套互不混淆的数据：`parent_id` 采区树（根节点为各采区配电室 / 变电所）+ `ring_link` 核心层 STP 环网（独立表、独立维护接口 `/api/ring-links`，无唯一上级）。`device_node` 上**已彻底删除** `peer_device_id / peer_port_id / peer_ip`，也没有 `POST /api/nodes/{id}/peer` 接口。
> 节点级别 `nodeLevel` 只描述采区树内层级：`0` 核心环网专属（不进采区树）、`1` 采区一级节点、`>=2` 采区内部设备，与「是否环网成员」正交。

## 启动

前提：后端 Spring Boot 服务已在 **8080** 运行（Swagger：<http://localhost:8080/swagger-ui/index.html>）。

```bash
cd E:/code/topology-console
npm start
# 或：node server.mjs
```

打开 **<http://localhost:5173>**。

自定义端口 / 后端地址：

```bash
PORT=5174 BACKEND=http://127.0.0.1:8081 node server.mjs
```

> 请通过 `http://localhost:5173` 访问，而不是直接双击 `index.html`。直接打开文件会因缺少代理而连不上接口。
>
> 后端从 IDEA 启动时请显式加 `--server.port=8080`，否则环境注入的 `SERVER_PORT` 会让端口漂移。

## 节点级别与拓扑类型（两套正交的语义）

| 角色 | topologyType | nodeLevel | 出现在哪 |
|---|---|---|---|
| 两台数据中心核心 | `RING` | `0` | **只**在「◉ 环形」视图 |
| 18 台采区变电所 / 配电室 | `RING` | `1` | 环形视图 + 作为「☰ 树形」每棵采区树的根 |
| 采区内部设备 | `TREE` | `>=2` | 「☰ 树形」视图，挂在所属变电所下 |

也就是说：**变电所既是环网成员，又是采区树的根节点**；核心交换机是环网成员但 `level=0`，因此不会污染采区树。

界面体现：

- 节点列表、节点详情、链路树、连接管理里都带级别标签：紫色「核心环网」、绿色「采区一级」、蓝色「采区 N 级」。
- 「新增节点」的**节点级别**下拉默认「自动推导」（无上级 = 1，有上级 = 上级+1）；选 `0` 时不能有上级，选 `>=2` 时必须有上级。断开 / 接入上级后后端会重算整棵采区树级别。
- 「查询当前节点链路」若选中 `level=0` 的核心节点，前端会直接拦截并提示改切「◉ 环形」（后端 `/chain` 也会返回 400）。
- 「新增节点」把**拓扑类型**切到「环网」时，「上级连接」卡片自动隐藏、「接入环网」卡片显示：环网节点不设上级，选一条现有环边插入即可（下拉只列 `RING` 链路，`CHORD` 不参与闭环）。提交调用 `POST /api/ring-links/{id}/insert-node`，成功后自动刷新节点列表、链路清单与环形图，闭环节点数 +1。

## 环网链路管理（「◎ 环网链路」）

环网互联的唯一权威数据源是 `ring_link` 表，`GET /api/topology/ring` 直接读它还原闭环。这一页通过 `/api/ring-links` 维护：

| 操作 | 说明 |
|---|---|
| 列表 | `GET /api/ring-links`，可按 `ringNo`（GREEN / RED / CORE）过滤；表格显示两端设备名与端口号 |
| 新增 / 编辑 | 选择 A / B 两端交换机（下拉只列交换机），按需选择各自端口；填写环编号、环上顺序、链路类型（`RING` 环上 / `CHORD` 直连弦）与备注 |
| 删除 | `DELETE /api/ring-links/{id}`，需二次确认；删除后环形拓扑立即按剩余链路重算 |

规则（后端强制）：两端必须是交换机且不能相同；端口非空时必须属于对应设备；同一对设备只能有一条链路（**不区分方向**，后端会把 `fromNodeId > toNodeId` 的边规范化为较小 id 在前并交换两端端口）。编辑时会把该链路的端口 id 回填到下拉。

保存后前端会重新拉取链路清单与 `/api/topology/ring`，环形图立即更新；删除节点时若设备仍被链路引用，后端会拒绝并要求先移除链路。

### 环网调整面板（摘除节点 / 改接链路 / 新增小环）

面板在「◎ 环网链路」页下方，三个操作都在**后端单事务**里完成，前端只负责选择、预览影响范围、执行后刷新数据。执行前都会二次确认，结果显示在「调整结果」区（原始响应 JSON）。

| 操作 | 面板字段 | 调用接口 | 实际发生的事 |
|---|---|---|---|
| **摘除节点 · 邻居自动直连** | 要摘除的环网节点、新链路备注（可选） | `POST /api/ring-links/nodes/{id}/bypass` | 删除该节点**全部**链路（含直连弦），新建一条 `RING` 链路把两个环上邻居连起来，端口继承旧链路邻居侧；**设备本身保留在库中**，只是脱离环网 |
| **改接链路一端** | 要改接的链路、被替换的一端、新接入交换机、新设备侧端口、保留侧端口、备注 | `POST /api/ring-links/{id}/rewire` | 把选中链路的指定端换成新交换机，另一端保持不变；环编号 / 顺序 / 链路类型 / 保留侧端口默认继承旧链路 |
| **新增小环 · 挂在主环节点上** | 挂接节点、环编号（留空自动分配 `SUBn`）、两台设备名称 / IP / 型号 / 位置、备注 | `POST /api/ring-links/sub-rings` | 单事务创建 2 台 `RING` 交换机（`level=0`、无 `parent_id`）+ 6 个自动避让的空闲光口 + 3 条 `SUBn / seq=1..3 / RING` 链路，构成「挂接点 ↔ A ↔ B ↔ 挂接点」自闭环；8 字图立即在挂接点外侧多一个小圆 |

挂接点下拉只列 **8 字主环上的非核心节点**（排除 `level=0` 主备与其它小环的专属设备），默认选中第一个并自动生成两台设备名与结构预览；留空环编号时预览会显示下一个可用的 `SUBn`。后端校验挂接点必须是交换机且已有主环 `RING` 链路，环编号格式非法 / 已占用 / IP 冲突都会整体回滚。

要点：

- **影响预览**：摘除前显示「将删除 N 条链路（环上 #x、#y，直连弦 #z），并新建 #A ↔ #B 保持闭环」；若该节点的环上链路不是恰好 2 条（枢纽节点），预览直接红字提示改用「改接链路」逐条调整，后端也会返回 400（API 层可用 `linkIds` 指定两条）。改接预览显示改接前后的两端对比。
- **端口下拉**：新设备侧端口按所选交换机加载；保留侧端口先同步填入原端口（接口慢 / 不可用也能用，留空即「继承原端口」），再异步补全该设备全部端口。
- **执行后**：`refreshAfterRingAdjust()` 清空端口缓存 → 重新拉节点列表、环网链路、`/api/topology/ring` → 重建面板下拉并重画环形图，闭环与小环结构立即更新。
- **失败回滚**：任一步校验不通过（非交换机、端点不匹配、端口不属于设备、两个邻居已有链路等）整个事务回滚，旧链路自动恢复，不会留下断环。

## 采区树形视图（「☰ 树形」规则）

**每棵树的根节点就是采区变电所**。这不是前端展示技巧，而是后端的数据语义：`/api/topology/full` 只枚举 `nodeLevel=1` 的采区变电所作为 `rootId`，`/chain` 沿 `parent_id` 回溯到的最初父节点也是该采区变电所；核心 `level=0` 与 `ring_link` 环网链路根本不进入链路数据。前端直接渲染后端返回的树，**不按环网 / 节点级别重排、不提供展示规则开关**。

> 注意区分两件事：`scope=branch` 是**数据范围裁剪**（决定「取哪条链路」），由后端按 `ancestorPath` 完成；旧后端忽略参数时前端 `pruneChainTree()` 用同样规则兜底。它不是「把采区树重新排一遍」的展示层剪枝，根节点仍然始终是采区变电所。「查询完整链路」永远是全部采区树、不裁剪。

| 规则 | 说明 |
|---|---|
| 根节点 | 每台 `nodeLevel=1` 的采区变电所 / 配电室就是一棵采区树的根（`rootId`），分组标题写「采区树 N/18 · 根节点 #X …」，树内标注「● 根节点 · 采区变电所」 |
| 采区内设备 | `nodeLevel>=2` 的分支原样挂在其所属采区变电所下，标题右侧显示「采区内设备 N 台」 |
| 环网互联 | 环网链路在 `ring_link` 表里，**不出现在 `/full` / `/chain` 响应中**，只在「◉ 环形」视图展示 |
| 核心枢纽 | 两台数据中心核心（`level=0`）不进树状图，只在「◉ 环形」视图展示 |

- 早期版本里的「采区为一级节点（隐藏环网串接）」勾选框与「后端原始展开树」对照视图**已移除**：两种视图在 v3 数据下渲染的是同一批树，开关没有实际作用。
- 「查询当前节点链路」只返回**当前节点所在的那一条链路**（1 棵按 `scope=branch` 裁剪后的树，上级只留主干），并把该采区标为蓝色边框「当前节点所属」；「查询完整链路」列出全部采区变电所的完整采区树（不裁剪）。
- 摘要里的「根节点（采区变电所）」直接对应接口 `rootId`；「查询节点到根的路径」对应 `ancestorPath`。

### 端口链路图（树形视图的渲染方式）

树形视图不再只列节点卡片，而是把**每台交换机的端口全部画出来**（前端零依赖 HTML 定位 + 底层 SVG 曲线）：

| 端口角色 | 位置 / 样式 | 数据来源 |
|---|---|---|
| 上级下联端口 | 节点卡**右侧**实色胶囊「X1 下联」；**仅上级有端口表时展示** | 子节点的 `parentPortId` / `parentPortNo` 回查上级 `ports` |
| 下级接入端口 | 子节点卡**左侧**描边胶囊「X1 接入」；**仅上下级都有端口表时展示** | 子节点的 `inboundPortId` / `inboundPortNo` |
| 成对连线 | 上级胶囊 → 下级接入胶囊的彩色贝塞尔曲线，中点 `↔`，悬停显示「上级端口 X ↔ 下级接入端口 Y」 | 前端按 `parent_id` 树边合成，模式 `paired` |
| 端口直连设备 | 上级下联端口胶囊的曲线**直接连到下级设备节点卡**，不画接入端口，中点 `→` | 上级有端口表、下级是无端口设备（视频 / 定位 / 广播 / NVR / 信号），模式 `direct` |
| 设备直连 | 两台设备节点卡之间一条灰色实线，**下联端口与接入端口都不展示** | 上级是无端口设备（摄像头菊花链等），模式 `plain` |
| 空闲端口 | 根节点卡**左侧**、其它设备卡**右侧**，彩色虚线胶囊「空闲」+ 虚线短枝 | 该设备 `ports` 减去上联 / 下联 / 环网占用 |
| 环网占用端口 | 紫色虚线胶囊「环网」 | `/api/ring-links` 的 `fromPortNo` / `toPortNo` 与设备 id 比对 |
| 旁支占用端口 | 橙色虚线胶囊「旁支」+ 虚线短枝，悬停写明被隐藏的设备 | 当前节点链路 `hiddenBranches` 的 `parentNodeId` + `parentPortNo` 与设备端口表比对；**不会被误标成空闲** |
| 无端口设备节点卡 | 第三行标注「无端口表 · 与上级直连」；**不再出现灰色「— 无端口」胶囊** | 该设备 `ports` 为空 |

**连接判定规则**（前端 `pgEdgeMode()`，以「设备是否登记过端口表」为准，只有登记了端口的交换机才算有端口）：

1. `paired` 上下级**都有端口表** → 下联端口 ↔ 接入端口成对标注；
2. `direct` **上级有端口表、下级是无端口设备** → 只展示上级下联端口，由该端口**直接接到下级设备**，不画下级接入端口；
3. `plain` **上级是无端口设备** → 接入端口与下联端口**都不展示**，两台设备节点卡直接相连。

真实 15502 采区树共 77 条边：`paired` 8 条、`direct` 23 条、`plain` 46 条；无端口设备的空闲端口仍照常展示（本批按约定只导入文本里出现过的端口，因此没有编造空闲口）。

- 端口颜色按端口号稳定映射（X1 红 / X2 橙 / X3 绿 / X4 青 / X5 蓝 / G1 紫 / G2 粉，其余哈希取色），同一端口在不同设备上颜色一致。
- 端口数据直接取链路树里后端 `enrich()` 填充的 `NodeVO.ports`；若命中旧 Redis 缓存导致该字段缺失，前端会并发回退 `GET /api/nodes/{id}/ports` 补齐。
- 每棵树单独一张可横向滚动的画布，递归测量子树高度后再排布，节点卡与端口胶囊不会重叠；点击节点卡仍可查看详情。
- 真实数据示例（2026-11-06 导入的 15502 采区树，树形视图第 15 棵）：端口列 `G2-G1` 落库为上级 `G2 下联` + 下级 `G1 接入`，`0-2-3-G1` 为 `0-2-3` + `G1`；摄像头菊花链（`……` 行）按真实树深度逐级展开，最深 12 级。

## 环形拓扑视图（「◉ 环形」· v3.3 8 字合成图）

**现场结构**：主备两台核心（`#1 数据中心核心一主` / `#2 数据中心核心一备`）在腰部相接，构成 **8 字形的左环 GREEN 与右环 RED**；两环共享这两台核心以及它们之间的 **CORE 直连边**；普通节点上还可挂小环（`SUBn`）。

**数据源**：`GET /api/topology/ring`。后端 `PhysicalRingAssembler` 按 `ring_no` + `seq_no` + CORE 共享边**显式组装物理环**（`ringMode=explicit`），返回 `cycles[].ringNo / subRing / anchorNodeId / sharedLinkIds`；`chords` 只剩真跨接弦，`mainCycle` 降级为兼容字段。前端 `figure8Svg()` 据此**合成一张 SVG**（不再是每个环一张图）。

渲染要点（**重点是拓扑结构 + 名称 / IP / 连接端口**）：

1. **一张 8 字图**：左环 GREEN 沿左侧半椭圆、右环 RED 沿右侧半椭圆，两端都汇聚到腰部两台核心；CORE 直连画成中间**紫色竖直实线**，`#1`/`#2` **全图只画一次**。
2. **小环从挂接节点向外鼓出**：按 `subRing` + `anchorNodeId` 找到主环上的挂接点，以它为切点向外侧画小圆，小环节点沿小圆均布；挂接点不重复绘制。多个小环挂在相邻节点时自动沿切向偏转 / 拉远避让，避免小圆与标题叠在一起；分组标题写明「SUB1 挂在 #7 … / SUB2 挂在 #8 …」。
3. 节点标注**名称 + IP + 状态点**，环边按 GREEN 绿 / RED 红着色并悬停显示「A端口 ↔ B端口」；「显示端口标注」默认勾选；未参与任何物理环的链路画成紫色虚线弦。
4. 图下方「**设备端口清单**」逐台列出全部端口，已接 `ring_link` 的标出对端，其余标「空闲」。
5. 顶部说明条、图例、分组标题都同步为「8 字双环 / 腰部共享直连 / 附属小环」，不再出现「跨环共享节点会在各环重复出现」这类旧文案。

**当前真实库**（`db/import-sub-ring-20261107.sql` 已执行，随后用新增小环接口创建 SUB2）：24 台环网设备 / 27 条链路；`cycles = GREEN 11 + RED 11 + SUB1 3（挂 #7 十四采区变电所，设备 #102/#103）+ SUB2 3（挂 #8 十三采区变电所，设备 #104/#105）`；`ringMode=explicit`、`chords=0`、`totalRings=4`。页面渲染 24 个节点、1 条腰部共享边、6 条小环边。SUB2 可用 `db/rollback-sub-ring-2-20261107.sql` 单独撤销。

**兼容与回退**：

- 后端是旧版或返回 `ringMode=cycle-basis`（无现场标注 / 断环）时，仍走 v3.1 的「每个 `cycle` 单独一张圆环图」渲染，不会报错。
- 闭环断开时 `ringOpenChains()` 按现存 `RING` 边画**开链视图**：n-1 条弧 + 红色虚线缺口 +「✕ 缺失链路 #A ↔ #B」，顶部提示断点设备名 / IP；只有一条开链时提供「**补回缺失链路（恢复闭环）**」按钮（`repairRingBreak()` 自动挑空闲端口、继承 `ringNo`/`seqNo`，确认后 `POST /api/ring-links`）。
- `chainQuerying()` / `chainFailed()` 在环形视图下**不再清空 `ringCanvas`**（环网数据源独立），采区链路查询期间 8 字图保持可见。

| 颜色 / 线型 | 含义 |
|---|---|
| 绿 / 红实线弧 | 左环 GREEN / 右环 RED 的环上物理链路（悬停看相接端口） |
| 紫色竖直实线 | 8 字腰部 CORE 直连 —— **两环共享的边**，不再算弦 |
| 蓝色小圆 | 挂在普通节点上的附属小环（`SUBn`） |
| 紫色虚线 | 未被任何物理环使用的跨接弦 |
| 红色虚线 | 断环时缺失的那条链路（仅开链视图） |
| 紫圈大圆点 | 共享枢纽 / 度数 > 2 的挂接点；蓝实心 = 当前选中 |

使用方式：打开页面默认「完整链路 + 环形视图」，点「☰ 树形 / ◉ 环形」切换；点击任意节点选中设备并刷新详情（含小环交换机 #102 / #103）。注意小环设备 `node_level=0`，不参与采区树，点「查询当前节点链路」会被后端拒绝并提示改用环形视图。

### 两种链路查询（前端分开）

| 按钮 | 做了什么 | 适用场景 |
|---|---|---|
| 查询当前节点链路 | 对当前选中节点调用一次 `/chain?scope=branch`：**上级只保留「采区变电所 → … → 查询节点」主干，查询节点的下级全部展开**；被裁掉的兄弟分支按上级端口收进 `hiddenBranches`，页面标「旁支」并给出隐藏提示 | 看某台设备接在上级哪个端口上、这条链路往下挂了什么设备 |
| 查询完整链路 | 调用 `/api/topology/full`，一次拿到全部 18 棵采区树；若后端尚未提供该接口，自动回退到前端聚合（枚举根节点 + 逐个 `/chain`） | 要看全网所有采区，或还原核心层环网闭环 |

`/full` 返回 `rootIds / chains / totalChains / totalNodes / statusSummary`；前端优先调用该接口，接口不可用时自动回退，摘要里会标注数据来源。

> 首次查询「完整链路」会触发后端对每台设备的真实 ICMP 探测，初始数据里的 `10.0.x.x` 是虚构地址，冷启动可能要几秒到十几秒；之后命中 5 分钟结构缓存会很快。

### 连接相关字段

| 场景 | 字段 |
|---|---|
| 新增节点 | `parentIp`（上级 IP，空 = 一级节点）、`parentPortNo`（上级是交换机时必填）、`inboundPortNo`（本级是交换机时必填）、`ports`（端口清单）、**`nodeLevel`**（留空自动推导）、`topologyType`（`TREE` / `RING`） |
| 插入环网节点（`insert-node`） | 节点基本信息 + `ports`（端口清单）、`fromPortNo` / `toPortNo`（新节点两侧本机端口号，须在 `ports` 中）、`nodeLevel`（留空默认 1）、`remark`；**不传 `parentIp`** |
| 摘除环网节点（`bypass`） | `linkIds`（可选，枢纽节点指定要断开的两条链路 id）、`remark`（可选）；body 可传 `{}` 或省略 |
| 改接链路一端（`rewire`） | `oldNodeId`（被替换端，必须是该链路端点）、`newNodeId`（新交换机）必填；`newPortId` / `keepPortId` / `remark` 可选，留空则继承原链路 |
| 新增 / 修改环网链路 | `fromNodeId`、`toNodeId`、`fromPortId`、`toPortId`、`ringNo`、`seqNo`、`linkType`、`remark` |
| 接入上级 | `parentIp`（必填）、`parentPortNo`、`inboundPortNo` |
| 修改节点描述 | **仅 `deviceName` / `deviceModel` / `location`**；IP / 设备类型 / 拓扑类型在界面上锁定只读 |
| 新增端口 | `portNo`、`portType`（`OPTICAL` / `ELECTRICAL`）、`remark` |
| 修改端口 | **仅 `remark`**；留空字符串表示清空备注 |

规则：交换机上级只能是交换机；上级是交换机记录「上级 IP + 上级端口」，上级是摄像头 / 广播只记录 IP；本级是交换机记录本机接入端口；禁止自连、成环、同一上级端口被多个下级占用——**成环检测只作用于采区树父子链，环网互联不走 `parent_id`**。

**兼容说明**：提交连接类请求时会附带 `parentId` / `parentPortId` / `inboundPortId`（按 id 连接），当前服务端会忽略这些未知字段。

## 常见问题

- **顶部状态灯红色**：后端没在 8080 运行，或 `BACKEND` 指错了，控制台所有接口请求会返回 502。
- **所有接口返回 500「字段 peer_device_id 不存在」**：8080 跑的是**删除 `peer_*` 之前的旧版后端进程**，而数据库已升级到 v3。请在 IDEA 里重新 Build / Restart `E:\code\network-topology`（记得加 `--server.port=8080`）；这是版本未对齐，不是数据丢失。
- **看不到 `/api/ring-links` / `/api/topology/ring`、节点没有级别标签**：同样是 8080 旧进程，重启后端即可；老库还要依次执行 `db/migrate-20261105-peer-topology.sql`、`db/migrate-20261105-node-level-ring.sql`、`db/migrate-20261105-drop-peer-fields.sql`。改完数据库直接 SQL 后记得清 Redis 的 `topology:*` 缓存。
- **环形视图只有一张圆环图 / 看不到 8 字腰部与小环**：8080 跑的是 v3.3 之前的后端——`/api/topology/ring` 没有 `ringMode=explicit` 与 `cycles[].ringNo`，仍按环基算法返回 1 个 20 节点假想大环。请在 IDEA 里重新 Build / Restart `E:\code\network-topology`（显式加 `--server.port=8080`）。旧后端下前端会自动回退到「每个 cycle 单独一张圆环图」，不会报错；重启后即变成一张 8 字图 + 3 个物理环。若「环网调整」执行报 404，则是更早的 v3.1 之前版本，同样需要重启。
- **摘除节点被拒绝，提示「需要恰好 2 条环上链路」**：该设备是枢纽（挂了小环或有直连弦），后端无法判断该保留哪两个邻居。前端预览会红字提示，可改用「改接链路一端」逐条调整；直接调 API 时可传 `linkIds` 精确指定两条。
- **新增的环网节点变成了某采区变电所的下级、环形图上找不到**：旧行为（已修复）。原因是早期版本把「上级连接」的 `parentIp` 也提交给 `RING` 节点，后端写进 `parent_id`、级别被推导为 `>=2`，且没有创建任何 `ring_link`。现在后端会直接拒绝 `RING + parentIp`，前端在环网模式下也隐藏了上级卡片；请使用「接入环网」选插入位置重建。已经产生的脏数据（例如 `#24 十五采区变电所` 挂在 `#8` 下）可在「连接管理」页删除后重新创建，或手工清理 `parent_id` 相关字段并把 `node_level` 改回 `1`。
- **树状图里找不到核心交换机、也看不到环网串接**：这是预期行为。后端 `/full` / `/chain` 只返回以采区变电所为根节点的采区树，核心层 `level=0` 环网只在「◉ 环形」视图展示；想核对接口原始结构，直接看浏览器的 Network 里 `/api/topology/full` 响应即可。
- **当前节点链路里看不到上级其它端口挂的设备**：v3.2 起这是预期行为 —— 上级只保留查询节点所在的主干，旁支被收进 `hiddenBranches`，其端口标为「旁支」并显示「已隐藏 N 条旁支」提示。想看整棵采区树请点「查询完整链路」，或直接调 `GET /api/nodes/{id}/chain?scope=tree`。
- **8080 还是旧后端，页面结果会不一样吗**：不会。前端请求始终带 `scope=branch`；旧后端忽略该参数、返回整棵树，前端 `pruneChainTree()` 会按 `ancestorPath` 做等价裁剪并补出 `hiddenBranches`。重启到新代码后由后端直接返回裁剪结果，页面表现一致。
- **树状图里采区比预期少**：「查询当前节点链路」只返回当前节点所在的一条链路；点「查询完整链路」可看到全部采区。
- **点核心节点查当前链路被拦截**：`level=0` 的核心环网节点不属于采区树，后端 `/chain` 返回 400；请切到「◉ 环形」视图，或在左侧选采区设备。
- **删除环网节点后环形图一片空白 / 显示「环网未闭合」**：`ring_link` 的两端外键是 `ON DELETE CASCADE`，删节点会连带删掉它两侧的环边，而原链路不会自动补回，`cycles` 变成 0。现在前端会画成开链视图并标出断点，点「补回缺失链路」即可恢复闭环；**预防**做法是删除环网节点前先走「◎ 环网链路 → 环网调整 → 摘除节点 · 邻居自动直连」，它会在单事务里把两个邻居直连、闭环不断。前端「删除节点」也会给这条警告。
- **环形视图提示「当前链路是树形拓扑，没有检测到闭合环」**：这是旧版前端或 `ring_link` 完全无数据时的提示；v3.2 起只要还有 `RING` 边就会显示开链视图。若一条链路都没有，检查「◎ 环网链路」页；旧后端 + 新数据库（环网 `parent_id` 已清空）也会出现这个提示，需重启后端到 v3。
- **链路查询慢**：后端会对链路上每个设备做真实 ICMP 探测，虚构地址会显示 OFFLINE，属正常。
- **删除节点被拒绝**：除了「有子节点」，还可能是该设备**被 `ring_link` 链路引用**。不要直接手工删链路再删节点（会断环），请改用「环网调整 → 摘除节点 · 邻居自动直连」。
- **端口被占用**：`PORT=5174 node server.mjs` 换端口即可。
- **想看数据库原始数据**：pgAdmin / DBeaver 连接 `127.0.0.1:5432/topology`（用户 `postgres`）。
